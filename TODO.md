# Что стоит попробовать дальше

## Член идемпотентности карты потока

**Что не так сейчас.** Ни один член лосса не проверяет, что уточнение не портит
уже верный черновик. `verify_kl` смотрит только вход `s = 0`; самокоррекция —
только `s ∈ [selfcorrect_s_min, 1)` и только на *собственном* черновике модели,
никогда на правильном ответе. Диапазон левее `s_min` не покрыт ничем.

**Чем это обернулось.** Замер 16 сентября 2026 (460 промптов, qkv на 63 582
шагах): расписание с точкой входа `s = 0.34`, то есть левее `s_min = 0.5`, роняет
приёмку на **−0.733 ± 0.055** относительно трёхпроходного, ухудшая результат на
90–97% промптов каждого из шести наборов. Сдвиг той же точки внутрь опоры
(`0 · 0.5 · 0.70 · 0.85`) даёт **4.128** — лучший результат кампании. Подробности
в [[decode-schedule-support]].

**Что требует полугрупповой закон.** Состояние собирается как
`x_s = (1−s)·ε + s·q`, карта есть `π_{s,1}`, и для `s < t < 1` закон
`π_{s,1} = π_{t,1} ∘ π_{s,t}` в форме, которую исполняет декодер, звучит так:

    q₁  = π_{s,1}(x_s)                     один длинный прыжок
    x_t = (1−t)·ε′ + t·q₁                  пересборка состояния в момент t
    q₂  = π_{t,1}(x_t)                     второй прыжок
    требуется: q₂ ≈ q₁

То есть лишнее уточнение не имеет права менять ответ.

### Вариант A — идемпотентность на правильном ответе (пробовать первым)

    L_fix = E_{s ~ U[0,1)}  D( π_{s,1}( (1−s)·ε + s·y* )  ‖  y* )

`y*` — жадное продолжение учителя, одно-горячее; оно уже посчитано, прохода
учителя не прибавляется. Смысл: зашумлённый ПРАВИЛЬНЫЙ ответ обязан
восстанавливаться в правильный при любом `s`. Вырождений нет — цель внешняя и
фиксированная. Покрывает весь диапазон `s`, включая необученную область.

Место — рядом с циклом самокоррекции, `flowdraft_block_wise.py`:

    s_fix = torch.rand_like(ones)
    prior = self.sample_prior(y_star, block_mask)
    x_fix = ((1.0 - s_fix[:, None, None]) * prior
             + s_fix[:, None, None] * y_star) * pad
    logits = self._df_forward(x_fix, anchor, ctx_mask, cache, s_fix, ones, df_kwargs)
    terms.append(self._teacher_loss(y_star, logits, live, position_weight=pos_w))

### Вариант B — самосогласованность цепочки, без учителя

    L_semi = E_{s<t}  D( sg[ π_{t,1}( (1−t)·ε′ + t·π_{s,1}(x_s) ) ]  ‖  π_{s,1}(x_s) )

Вырождение ЕСТЬ и очевидное: постоянная карта обнуляет член точно. Годится
только как добавка к заякоренным членам, с малым весом, никогда сама по себе.

**Направление тяги менять нельзя.** Отцепить композицию и тянуть одиночный
прыжок — это дистилляция двух проходов в один, она сотрёт ровно то
преимущество, которое мы измеряем. Отцеплять надо одиночный прыжок и тянуть
композицию: «уточнение не имеет права портить то, что уже верно».

**Цена.** Плюс один проход черновика на шаг, ноль проходов учителя. Одно плечо
композиции уже считается в цепочке самокоррекции.

**Как ставить.** Отдельная ветвь обучения, честно сравнимая только при
согласованном бюджете, то есть после того, как нынешняя пара дойдёт до 80 000.

## Смежное, из того же разбора

- **Он-полиси выживание вместо статического профиля.** `_survival_weights`
  считает `dE/da_j = S_{j−1}(1 + R_j)` точно, но питается неподвижным
  `acceptance_profile: [0.8]`. Заменить на измеренную попозиционную приёмку
  модели, отцепленную от графа: маска принятых токенов входит в лосс как ВЕС,
  то есть вероятность дойти до позиции, а не как третья цель.
- **Маска принятых бесполезна как отдельный якорь.** При жадной верификации она
  есть детерминированная функция черновика и учителя, поэтому триплетный лосс по
  тройке «правильный ответ — восстановленный — принятые» не даёт ни одного
  градиентного направления сверх пары. Это та же теорема, что и об отсутствии
  бесплатной многошаговости при детерминированном верификаторе.
- **Калибровка.** Жадная приёмка читает только argmax, поэтому цель «принять всё»
  определяет черновик лишь с точностью до argmax и обнуляет градиент всюду, где
  позиция уже принята. При спекулятивном СЭМПЛИРОВАНИИ приёмка равна `1 − TV`,
  то есть читается всё распределение: загон в one-hot максимизирует жадный режим
  и минимизирует сэмплирующий. Замерить TV на готовых чекпоинтах — мак, без
  квоты, пара часов; это скажет, успели ли мы продать сэмплирующий режим.
