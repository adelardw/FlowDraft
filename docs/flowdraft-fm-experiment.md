## Гипотеза и границы

**Последнее уточнение пользователя, дословно:** «то есть мой refinement (ms) +
MSE на скорости - тот, что во flow-matching».

Цель: получать совместное распределение блока из L токенов, близкое к
последовательному AR-сэмплированию, за один или несколько проходов драфтера:

```math
P_{\mathrm{AR}}(Y_{1:L}\mid c)=\prod_{j=1}^L P_{\mathrm{AR}}(Y_j\mid c,Y_{<j}).
```

Это цель для сырых предложений, а не только для итогового текста после
AR-проверки. Совпадения маргиналов отдельных позиций недостаточно.

Реализована сумма **FM-MSE по скорости + исходный взвешенный multistep KL**.
Прежняя замена multistep KL на MSE была ошибочным прочтением запроса и удалена.
Отдельного loss первого прохода в этой сумме нет. Оба члена используют одно
поле, связанное с вероятностным прогнозом формулой q=X+(1−t)v.

Это согласует параметризацию, но не доказывает совпадение оптимумов двух целей,
отсутствие конфликта градиентов или устойчивую сходимость на 0.6B. AR-ответ
на дискретный черновик не равен posterior endpoint при условии непрерывного
состояния, нужному для точного FM-поля. Multistep term остаётся дополнительной
целью исправления черновиков. Точное совпадение совместного распределения с AR
и качественная генерация за один FP **не установлены**.

## Модель и геометрия

- Бэкбон: Qwen3-0.6B. Исходные AR-веса, embedding и LM head заморожены.
- Обучаются Q/K/V-копии драфтера и существующий time embedding; исходная AR
  не обновляется. Новая неограниченная голова скоростей не добавлена.
- `A = anchors_per_sequence` — число якорей; `L = block_size - 1` — число
  предсказываемых позиций после каждого якоря. В начальном конфиге `A=1`, `L=31`.
  Несколько якорей поддерживаются тем же отдельным классом.
- Каждый якорь задаёт свою условную задачу. Он видит свой исходный префикс и
  свой зашумлённый блок; чистое будущее и другие блоки в attention недоступны.
- Якорь остаётся чистым. Поток и loss действуют только на новые позиции.
- Входные состояния имеют форму `[B,A,L,V]`, упакованный вход вместе с якорями —
  `[B,A*(L+1),V]`, эмбеддинги — `[B,A*(L+1),d_model]`.

## Откуда берётся target

FM получает следующие L токенов Y из поданного датасета. Их one-hot
представление задаёт X1. Один frozen AR FP даёт общий KV-кеш; его corpus logits
не используются как отдельная цель первого прохода. Затем все дискретные
черновики собственной Euler-траектории проверяются одним дополнительным AR FP.
Причинные маски закрывают другие черновики и чистое будущее.

**Пока FM-данные — обычный корпус**, унаследованный из базового data config.
Это прототип двухчленного loss, а не завершённая дистилляция совместного AR-закона.
Чтобы FM учил именно AR-распределение, можно использовать полные блоки,
сэмплированные из замороженного AR с зафиксированной политикой sampling,
например подготовленные заранее. Альтернатива — importance-коррекция proposal,
выведенная в разделе согласования ниже; её дисперсия пока препятствует простому
переносу на длинные блоки. Greedy-продолжения не представляют всё стохастическое
распределение. Источник новых данных ещё не подготовлен и обучение не запускалось.

Один AR FP умеет оценить условные вероятности всех позиций **готового** блока.
Он не генерирует полный точный AR-блок из одного префикса параллельно.
Для текущего непустого training step:

| Работа | AR FP | DF FP |
|---|---:|---:|
| Контекстный кеш | 1 | 0 |
| FM на случайном интерполянте | 0 | 1 |
| Собственная траектория из N шагов | 0 | N |
| Общая проверка всех N черновиков | 1 | 0 |
| Итого | 2 | N+1 |

Стоимость предварительного AR-сэмплирования в эту таблицу не включена.
Второй AR FP обрабатывает N×A блоков, поэтому его FLOPs и память растут с N.
При N=1 он нужен для метрики приёмки; multistep loss в этом случае равен нулю.
Исходный KV-кеш не загрязняется черновиками.

## Шум, время и вход сети

```math
X_1=\operatorname{onehot}(Y),\quad
X_0\sim\mathcal N(0,\sigma^2 I),\quad \sigma=1,
\qquad t\sim U[0,1),
\qquad X_t=(1-t)X_0+tX_1.
```

Для каждого блока выбирается одно время, общее для всех его L позиций.
Начальные шумы независимы по позициям и компонентам; сеть видит весь блок.
В этой модели Gaussian **не делится на `sqrt(V)`**. Промежуточное состояние
не обязано лежать в симплексе; отрицательные значения допустимы.

Чтобы не подавать огромные нормы в замороженную embedding-проекцию, только
вход сети нормализуется детерминированным коэффициентом:

```math
r(t)=\sqrt{(1-t)^2 V\sigma^2+t^2},\qquad
H_t=(X_t/r(t))E+\operatorname{time\_embed}(t,t).
```

Само состояние ODE, prior и формулы loss этой нормализации не подвергаются.
Якорь получает обычный token embedding, с существующим кондиционированием
чистого слота на `(1,1)`. Нормализация не является обучаемой проекцией и не
обещает устранить потерю информации при `V -> d_model` через замороженную E.
Это ограничение аппроксимации поля, которое нужно учитывать при интерпретации.

## FM-член

Сеть использует существующий LM head для параметризации поля:

```math
q_\theta(X_t,t,c)=\operatorname{softmax}(\operatorname{logits}_\theta),
\qquad
v_\theta(X_t,t,c)=\frac{q_\theta(X_t,t,c)-X_t}{1-t},
\qquad U=X_1-X_0.
```

Дополнительный FM-loss — взвешенная регрессия скорости:

```math
\mathcal L_\mathrm{FM}
=\mathbb E\left[\frac{1}{M}\sum_{b,a,j}m_{baj}
(1-t_{ba})^2\|v_{\theta,baj}-U_{baj}\|_2^2\right],
\quad M=\sum_{b,a,j}m_{baj}.
```

Норма суммирует компоненты словаря, среднее берётся по живым позициям, без
якорей. В текущей подготовке выбираются полные валидные окна; пустой batch
даёт связанный с параметрами нулевой loss и проходит общую проверку конечности.

На выбранном линейном интерполянте это **в точности** равно:

```math
\mathcal L_\mathrm{FM}
=\mathbb E\left[\frac{1}{M}\sum_{b,a,j}m_{baj}
\|q_{\theta,baj}-\operatorname{onehot}(Y_{baj})\|_2^2\right].
```

Код вычисляет вторую форму, `sum(q*q) - 2*q[target] + 1`, чанками по 64 позиции.
Она не требует вычитания больших скоростей около t=1. Это Brier loss,
алгебраически эквивалентный выбранному **взвешенному** MSE по скорости,
а не невзвешенному FM и не cross-entropy. Равенство значений и градиентов
проверяется тестом. Время всё равно входит в состояние и в сеть.

У отдельно взятого FM-члена при положительном весе для t<1 популяционный оптимум
остаётся условной средней скоростью для распределения корпуса. После добавления
членов по ответам AR ниже оптимизируется гибридная цель; прежняя характеристика её полного
оптимума не гарантируется. Это также не гарантия конечной нейросети.
Brier loss через softmax может давать слабые начальные градиенты при большом
словаре; корректность формулы не доказывает хорошую сходимость на 0.6B.

## Исходный multistep loss на той же модели

Во время обучения N выбирается равномерно из `fm_train_steps: [1,2,3,4]`.
Сетка — t_i=i/N. На независимом начальном Gaussian строится траектория:

```math
q_i=q_\theta(X^{(i)},t_i,c)
=X^{(i)}+(1-t_i)v_\theta(X^{(i)},t_i,c),\qquad d_i=\arg\max q_i,
\qquad
X^{(i+1)}=\operatorname{sg}\left[X^{(i)}+
(t_{i+1}-t_i)v_\theta(X^{(i)},t_i,c)\right].
```

Индекс i идёт от 0 до N−1. В конце X^(N)=q_(N−1). Градиент проходит через
каждый отдельный forward, но не между состояниями. FM-forward на интерполянте
и эта траектория используют независимые шумовые выборки.
`selfcorrect_rounds` не управляет числом проходов: это настройка старого цикла.

Учитель отвечает на предыдущий дискретный черновик:

```math
P_{i-1,j}=\operatorname{sg}P_\mathrm{AR}(\cdot\mid c,(d_{i-1})_{<j}).
```

Сохраняются исходные веса приёмки:

```math
u_j=\frac{\partial\mathbb E[A]}{\partial a_j}
=S_{j-1}(1+R_j),\quad S_{j-1}=\prod_{r<j}a_r,
\quad R_j=a_{j+1}(1+R_{j+1}),\quad R_L=0,
\qquad
b_{i,j}=\begin{cases}
1,&j\text{ — первый отказ в }d_{i-1},\\
0.5,&\text{остальные позиции}.
\end{cases}
```

`acceptance_profile: [0.8]` задаёт фиксированный опорный профиль для u.
Коэффициент 0.5 получают и уже принятые позиции, и позиции после отказа.
Вес обозначен b, чтобы не путать его с вектором скорости v.
Corpus gate g относится к прежнему отдельному first-pass term и в ms не входит;
этот first-pass term не добавлен в новую двухчленную цель.

```math
\mathcal L_\mathrm{ms}=
\frac1{N-1}\sum_{i=1}^{N-1}
\frac{\sum_j u_j b_{i,j}\,
\mathrm{KL}\left(P_{i-1,j}\|q_{i,j}\right)}
{\sum_j u_j b_{i,j}}\qquad(N>1).
```

При N=1 этот член равен нулю. В формуле опущены live mask и индексы батча/якорей;
реализация делит на фактическую массу весов живых позиций всего батча.
Переиспользуются исходные `_teacher_loss` и `_survival_weights`.
Ответ на последний черновик используется только для метрики `accepted`.
Для L=3 и a=0.8 веса u пропорциональны [2.44,1.44,0.64]; первый отказ на второй
позиции даёт произведение [1.22,1.44,0.32] с массой 2.98.

**Связь с полем:** KL считается по q_i=X^(i)+(1−t_i)v_i, а не по signed-вектору
v_i, который не является вероятностным распределением. В коде q задаётся
softmax LM logits, поэтому валиден для KL, а скорость определяется через q.
Это одна параметризация, без независимых голов с несвязанными предсказаниями.
Тест проверяет совпадение KL и его градиентов с явным восстановлением q из v.

### Полная цель и логирование

```math
\mathcal L=\lambda_\mathrm{FM}\mathcal L_\mathrm{FM}
+\lambda_\mathrm{ms}\mathcal L_\mathrm{ms}.
```

В пресете `fm_weight=selfcorrect_kl_weight=1`. Эти веса ещё не подобраны на GPU.
`verify_kl_weight=0`: отдельного first-pass KL нет. Старые `verify_velocity_weight`
и `selfcorrect_velocity_weight` отклоняются, если заданы ненулевыми.
Логируются `fm`, `selfcorrect_kl`, приёмка и число Euler-шагов. Пустой batch
использует те же ключи и коллективную проверку конечности loss.

Исходные KL, коэффициенты, target предыдущего черновика и stop-gradient
сохранены. Входы уточнений адаптированы к Euler-траектории вместо старого
перезапуска `(1-s)*fresh_noise+s*q`. Это перенос multistep term на поток,
а не побитовое воспроизведение старого training forward.

Совместимость targets не следует из равенства q=X+(1−t)v. Например, FM может
уверенно распознавать endpoint из X_t, а AR, не получающий X_t, оставаться
неуверенным. Тогда два члена тянут q в разные стороны. До дорогой кампании
нужно проверить масштабы и направления их градиентов и обе кривые loss.
CPU-тесты проверяют формулы и граф вычислений, не отсутствие такого конфликта.

## Сэмплирование

На один блок один раз выбирается X0. Для сетки `0=t0<...<tN=1`:

```math
X_{i+1}=X_i+(t_{i+1}-t_i)v_\theta(X_i,t_i,c)
=X_i+\frac{t_{i+1}-t_i}{1-t_i}(q_\theta(X_i,t_i,c)-X_i).
```

`jumps=N` задаёт N равномерных шагов Эйлера; также можно задать явную непрерывную
сетку. Четыре шага — `0 -> .25 -> .5 -> .75 -> 1`. Шум между шагами не
пересэмплируется; промежуточные состояния не обрезаются и не нормализуются как
вероятности. Поле не вычисляется при t=1. Последний шаг имеет коэффициент 1,
поэтому его результат присваивается как q для численной устойчивости.

Рестарты вида `[(0,1),(.5,1),(.75,1)]` отклоняются: это другая процедура.
Сеть обусловлена только текущим временем `(t_i,t_i)`; правый конец шага
используется решателем, а не задаёт обученную карту конечного скачка.

- `sample_block(prefix, block_size=32, steps=4, seed=...)` выдаёт сырой блок
  без AR-проверки: после последнего шага берётся argmax. Разнообразие возникает
  из начального шума; для изучения распределения нужно менять seed. Префикс
  включает последний чистый якорь. `decode.fixed_prior` должен быть false.
- `generate(..., jumps=4)` использует поток как drafter и затем штатную AR-проверку.
  Greedy и coupled sampling проверяются против обычного AR. Uncoupled sampling
  использует дополнительную категориальную выборку из конечного q и штатное
  speculative acceptance; это отличается от сырых ODE-выборок с argmax.
- Новые inference-методы включают eval на время вызова и восстанавливают режим.

Один большой шаг Эйлера не гарантирует совместность. Для отдельно взятого FM
с независимым coupling X0 и X1 идеальное q при t=0 — условные маргиналы,
независимые от шума; один шаг сразу выдаёт их. Поэтому N=1 остаётся важным
контролем, а не обещанием однопроходного мультимодального генератора. Основные
бюджеты оценки — N=1/2/3/4. N=8, если измерять отдельно, будет проверкой переноса
за пределы числа собственных шагов, использованных в обучении multistep term.

## Запуск и проверка

Конфиг: [qwen06_flowdraft_fm.yaml](../src/configs/experiment/qwen06_flowdraft_fm.yaml).
Код: [flowdraft_fm.py](../src/models/flowdraft_fm.py).

Горизонт выбирается **до** старта вместе с расписанием. Команда-шаблон, не
свидетельство запуска (переменная намеренно не имеет значения по умолчанию):

```bash
: "${FLOWDRAFT_FM_STEPS:?Set the agreed fixed training horizon first}"
uv run python src/train.py +experiment=qwen06_flowdraft_fm \
  trainer.max_steps="$FLOWDRAFT_FM_STEPS"
```

Конфиг наследует исходный текст из штатного data config. Перед сравнением нужно
зафиксировать пул, число уникальных префиксов, anchors, seeds и бюджет данных.
Онлайн-генерации обучающих текстов учителем здесь больше нет. Corpus targets
и teacher feedback выполняют разные роли; дополнительные цели от AR не превращают сам
FM-член в точную дистилляцию распределения AR.
fp16 для T4 указан в конфиге, но память, скорость и устойчивость на T4 ещё не проверены.

Локальные проверки без загрузки весов и без GPU:

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_flowdraft_fm.py' -v
```

Проверяются: FM-loss и его градиенты; исходный взвешенный multistep KL и его
градиенты; совпадение KL с явным восстановлением endpoint из скорости;
соответствие targets предыдущему черновику; общая проверка всех черновиков
против раздельных проверок и обычного причинного AR; сохранность KV-кеша и исходных весов; backward
при одном/нескольких якорях и пустом batch; непрерывный Euler без нового шума;
сырая генерация двух связанных мод с аналитическим полем; greedy/coupled
эквивалентность; два CPU-шага Lightning и загрузка сохранённого драфтера через
factory. Тест с аналитическим полем проверяет решатель, а не качество обученной
нейросети. Реальный DDP/CUDA запуск этим не покрыт.

## Следующие измерения

1. Проверить вычислимую оценку posterior-target из следующего раздела на собственных

## Согласование FM и ms: общий posterior target

Уточнение от 06.11.2026 по просьбе пользователя «попробуй согласовать».
Это следующая математическая постановка, а не описание уже включённого Qwen training path.

Пусть P(Y|c) — полный совместный закон замороженной AR при выбранных temperature,
top-k/top-p. Для X_t=(1−t)ε+t onehot(Y), ε∼N(0,σ²I), определим:

```math
\kappa_t(x\mid Y)\propto
\exp\left[-\frac{\|x-t\operatorname{onehot}(Y)\|^2}{2\sigma^2(1-t)^2}\right],
\qquad
R_t(Y\mid x,c)=\frac{P(Y\mid c)\kappa_t(x\mid Y)}
{\sum_{Y'}P(Y'\mid c)\kappa_t(x\mid Y')},
\qquad R_{t,j}(v)=\sum_{Y:Y_j=v}R_t(Y\mid x,c).
```

R — распределение **целого конечного блока с учётом текущего непрерывного
состояния**. Учитывается всё x, включая будущие позиции. Нельзя заменить его
на AR-прогноз по одному черновику, даже добавив локальный noise likelihood к
его logits: информация из других позиций тоже меняет posterior.

Для FM с endpoints именно из P, при фиксированных x,t,c:

```math
\mathbb E_{Y\sim R_t}\left[(1-t)^2
\left\|v_\theta-\frac{\operatorname{onehot}(Y)-x}{1-t}\right\|^2\right]
=\|q_\theta-R_t^{\mathrm{marg}}\|^2+C(x,t,c),
\qquad q_\theta=x+(1-t)v_\theta.
```

Здесь C не зависит от параметров. Оптимальный q равен маргиналам R_t. Поэтому
согласованный multistep term на собственном Euler-состоянии X^(i) имеет вид:

```math
\mathcal L_{\mathrm{ms}}^{\mathrm{aligned}}=
\frac1{N-1}\sum_{i=1}^{N-1}
\frac{\sum_j u_jb_{i,j}\,
\mathrm{KL}\left(\operatorname{sg}R_{t_i,j}(\cdot\mid X^{(i)},c)\|q_{i,j}\right)}
{\sum_j u_jb_{i,j}},
\qquad
\mathcal L=\lambda_{\mathrm{FM}}\mathcal L_{\mathrm{FM}}
+\lambda_{\mathrm{ms}}\mathcal L_{\mathrm{ms}}^{\mathrm{aligned}}.
```

Сохраняются собственная траектория, stop-gradient между уточнениями, u_j,
коэффициенты первого отказа 1/0.5 и нормировка по их массе. **Меняется teacher
target внутри ms**: ответ AR на предыдущий дискретный префикс заменён posterior
на текущем непрерывном состоянии. Это необходимая адаптация, а не тождественное
преобразование исходного ms-loss. Предыдущий черновик остаётся источником
состояния, verdict-весов и предложения кандидатов для оценки posterior.

При точном R и достаточно выразительном классе моделей оба члена имеют общий
популяционный оптимум q=R. Более того, на одном состоянии для независимых logits
градиенты условного среднего FM-loss и KL не направлены противоположно:
при d=q−R и J=diag(q)−qqᵀ их скалярное произведение пропорционально dᵀJd≥0.
Положительные фиксированные position weights это свойство не меняют.
Это не утверждение о каждом шумном sample-gradient, общих параметрах нейросети,
разных обучающих состояниях или ограниченной embedding-проекции V→d_model.
При ограниченной модели и приближённом R конфликты градиентов всё ещё возможны.

### Как оценивать R через один батч AR-проверки

На шаге i из предыдущего q выбираются M **целых** блоков Y^(m) с известной
плотностью r_i. Например, это независимые categorical-выборки по позициям из
`(1−ε) sg(q_(i−1)) + ε/V`, где ε>0 обеспечивает полную поддержку.
Это специально определённое proposal для обучения; r_i нельзя подменять
неизвестной вероятностью результата `argmax(ODE(noise))`.

AR оценивает log P(Y^(m)|c)=Σ_j log P_AR(Y_j^(m)|c,Y_<j^(m)). Все готовые
кандидаты можно упаковать в один причинно изолированный батч. При ограничении
памяти потребуются отдельные чанки и несколько FP. Веса кандидатов:

```math
\ell_m=\log P(Y^{(m)}\mid c)-\log r_i(Y^{(m)})
+\frac{t_i}{\sigma^2(1-t_i)^2}\sum_j X^{(i)}_{j,Y_j^{(m)}},
\qquad \bar w=\operatorname{softmax}(\ell),
\qquad \widehat R_{i,j}(v)=\sum_m\bar w_m\mathbf1\{Y_j^{(m)}=v\}.
```

Общие для всех кандидатов Gaussian-слагаемые сокращены; это верно для one-hot
endpoints одинаковой длины. Веса и target отделяются от градиента. Отношение
P/r обязательно: без него кандидаты дополнительно смещают target к proposal.
При конечном M это self-normalized importance sampling — **смещённая оценка**,
а не точный posterior. Стоимость AR-проверки растёт как M×число уточнений×якоря.

### FM без последовательного AR-сэмплирования на каждом training step

Можно заранее сэмплировать AR-endpoints. Другая математическая возможность —
известное proposal r с полной поддержкой и **ненормированные** importance-веса:

```math
\mathcal L_{\mathrm{FM}}=
\mathbb E_{Y\sim r,\epsilon,t}\left[
\operatorname{sg}\frac{P(Y\mid c)}{r(Y)}\,
(1-t)^2\|v_\theta((1-t)\epsilon+t\operatorname{onehot}(Y),t,c)
-(\operatorname{onehot}(Y)-\epsilon)\|^2\right].
```

Если proposal зависит от зафиксированного черновика или шума, в r учитываются
эти условия. В точном ожидании значение и градиент соответствуют FM на AR-законе;
тест проверяет это равенство. Нормировка текущих M весов до суммы 1 либо clipping
вносят смещение. Ненормированный вариант может иметь огромную дисперсию.
Поэтому отсутствие последовательного teacher rollout ещё не делает этот путь
дешёвым или устойчивым на T4.

### Проверка на собственных состояниях драфтера

На том же бинарном AR обучен MLP: вход `[flatten(X), t]`, два скрытых слоя
по 128 с SiLU, выход `[31,2]`. Только FM, 2000 Adam-шагов, lr=0.002,
batch=64, train seed=912. Взяты 100 собственных четырёхшаговых Euler-траекторий,
eval seed=9137. Все вычислители posterior сравниваются на одних состояниях.

Проверен proposal, сохраняющий связи через общий целый блок-родитель:

```math
r(Y)=\sum_{b\in B}\pi_b(X,t)\prod_j
\left[(1-\delta)\mathbf1\{Y_j=b_j\}+\delta q^{\mathrm{floor}}_j(Y_j)\right].
```

Банк содержит 256 независимых AR-продолжений, seed=7319. Веса родителей —
Gaussian likelihood с 10% uniform floor; δ=0.15, локальные вероятности —
`0.9 q_previous + 0.1 uniform`. Плотность r считается явно, в posterior
остаётся поправка P_AR/r. Это **proposal для полного AR**, не эмпирический
целевой закон следующего подраздела.

не даёт. Малая поздняя ошибка на истинных интерполянтах выше не переносится
автоматически на собственные состояния драфтера.

### Вычислимый вариант: один фиксированный банк для обоих loss

Для каждого префикса c заранее сэмплируется и фиксируется один банк полных
продолжений B(c)={Y¹,…,Yˢ} из замороженной AR. Его эмпирический закон:

```math
P_B(Y\mid c)=\frac1S\sum_{s=1}^S\mathbf1\{Y=Y^s\},\qquad
a_s(x,t)=\operatorname{softmax}_s\left[
\frac{t}{\sigma^2(1-t)^2}\sum_j x_{j,Y^s_j}\right],\qquad
R^B_{t,j}(v)=\sum_s a_s(x,t)\mathbf1\{Y^s_j=v\}.
```

FM выбирает endpoint равномерно **из того же банка**. На собственном состоянии
ms использует точный R^B. Полная цель и сэмплер:

```math
\mathcal L_{\mathrm{FM}}^B=
\mathbb E_{Y\sim P_B,\epsilon,t}(1-t)^2
\|v_\theta((1-t)\epsilon+t\operatorname{onehot}(Y),t,c)
-(\operatorname{onehot}(Y)-\epsilon)\|^2,
```

```math
\mathcal L_{\mathrm{ms}}^B=
\frac1{N-1}\sum_{i=1}^{N-1}
\frac{\sum_j u_jb_{ij}\mathrm{KL}(\operatorname{sg}R^B_{t_i,j}(\cdot\mid X_i,c)\|q_{i,j})}
{\sum_j u_jb_{ij}},\qquad
\mathcal L=\mathcal L_{\mathrm{FM}}^B+\lambda_{\mathrm{ms}}\mathcal L_{\mathrm{ms}}^B,
```

```math
v_i=\frac{q_i-X_i}{1-t_i},\qquad
X_{i+1}=X_i+(t_{i+1}-t_i)v_i,\qquad X_0\sim\mathcal N(0,\sigma^2I).
```

При N=1 ms=0. В тесте λ_ms=1, σ=1, N равномерно выбирается из 1/2/3/4,
состояния между проходами отделены от градиента. Сохраняются исходные веса
u при reference acceptance=0.8 и b=1 в первой отвергнутой позиции, 0.5 во всех
остальных, включая принятый префикс. Вердикт берётся по предыдущему черновику
от исходного AR; общий posterior target учитывает всё текущее X.

Для **P_B** оба члена имеют один точный популяционный оптимум. Posterior не
требует AR FP: Gaussian scores считаются по S×L выбранным координатам X.
Это стоимость весов кандидатов; сам нейросетевой FP и vocab-loss всё ещё нужны.
Повторяющиеся строки банка сохраняют свою частоту. Дополнительно умножать их
на P_AR нельзя: это изменит эмпирический закон. Банк должен быть привязан к
точному префиксу/якорю; случайный новый банк на каждом ms-запросе не обеспечивает
такого же доказательства общей цели. Оба loss должны видеть один фиксированный
закон для данного условия c.

Цена: генерация S полных AR-продолжений **на каждый префикс** заранее и их
хранение. У toy один безусловный контекст; для реальных текстов этот расход
ещё не измерен. S=256 — параметр CPU-проверки, не выбранный бюджет Qwen.
P_B приближает P_AR, но не совпадает с ним. Здесь устранена ошибка вычисления
posterior относительно банка, а не ошибка самого банка относительно учителя.

описана ниже. В прежнем `FlowDraftFM` FM-endpoints всё ещё корпусные, а ms-target
исходный; CPU-результаты выше нельзя приписывать этому классу. Для произвольного AR задача
дешёвого точного posterior остаётся открытой; lossless-выход обеспечивается
корректной AR-проверкой. Согласование loss не гарантирует lossless сырой блок.

## Следующий этап: Qwen3-0.6B, 80k примеров, 4 якоря, 60k шагов

Прямое разрешение пользователя: «Добавь 4 якоря и давай 60к шагов».
Разрешение на перенос данных в приватный датасет нового аккаунта также получено.

- Модель: Qwen3-0.6B, frozen AR; обучаются только копии Q/K/V и time embedding.
  HF revision `c1899de289a04d12100db370d81485cdf75e47ca` фиксирован.
- Отдельный класс [FlowDraftFMBank](../src/models/flowdraft_fm_bank.py), конфиг
  [qwen06_flowdraft_fm_bank.yaml](../src/configs/experiment/qwen06_flowdraft_fm_bank.yaml).
  Старые FlowDraft, Orthrus и адаптер за опубликованными числами не менялись.
- Ровно 80 000 исходных примеров Nemotron chat/code/math, round-robin из прежних
  parquet; отдельные первые 32 строки для validation. Chat template Qwen,
  truncation/right-padding до 256, **без упаковки разных документов**. Это новый
  протокол, не продолжение старой packed-кампании. Подготовка: `ops/fm_prepare.py`.
- SHA256 `tokens.pt`: `deff069dfa72a2dcef3e5d85d8da407f544b86afe28cdaf713146fc4ded02af6`.
  Размер файла около 102.4 MB. Исходные SHA256 сохранены в его manifest.
- Четыре различных якоря на строку выбираются детерминированно по её токенам и
  seed=42. Позиции этих якорей повторяются в следующих эпохах; это позволяет
  ограничить число условных банков. На якорь 31 новый токен (`block_size=32`).
- Банк: **16** полных AR-продолжений на точный префикс, temperature=1, без
  top-k/top-p и без остановки внутри фиксированного 31-токенного блока по EOS.
  16 — рабочий размер нового GPU-эксперимента; toy-результат получен при 256 и
  автоматически на него не переносится. Это дополнительное приближение AR.
- Банк создаётся лениво замороженной AR при первом посещении префикса. Хеш
  самого префикса задаёт отдельный seed; SQLite хранит prefix + все samples,
  повторяющиеся samples не удаляются. Одинаковый префикс переиспользует банк.
  На повторных посещениях AR-rollout не нужен. Теоретический верхний объём
  первой подготовки: 80 000×4×16×31 = **158 720 000 AR-токенов**; общие префиксы
  уменьшают его. Это существенная стоимость, которую нужно измерить на T4.
- Сохраняются оба согласованных loss из раздела выше, λ_FM=λ_ms=1, σ=1,
  N∈{1,2,3,4}; u при reference acceptance=0.8, первый отказ 1, остальные 0.5.
  Для posterior нужны только координаты X у токенов банка; sparse KL корректно
  объединяет повторяющиеся token IDs и не строит плотный teacher target.
- Microbatch=1, накопление=16, один GPU. Итого 16 строк / 64 якорных блоков на
  шаг оптимизатора; 60k шагов дают 960k предъявлений строк и 3.84 млн блоков.
  Фиксированный пул проходит 12 раз с детерминированной перестановкой каждой
  эпохи. Resume учитывает уже пройденные эпохи и не меняет состав 80k-пула.
- LR=3e-4, cosine на **60 000** шагов, warmup=3000. При resume проверяется
  неизменность горизонта, числа якорей, размера блока и банка. Вместе с полным
  optimizer/scheduler checkpoint переносится SQLite; потерянный банк приводит
  к ошибке, а не к тихой подмене target.

### Сэмплирование, которое нужно исследовать

Во время инференса не нужны ни датасет, ни SQLite-банк. Для одного контекста
берётся новый Gaussian X0 формы `[1,31,V]`. Каждый FP вычисляет поле для всех
31 позиций совместно. При четырёх равных шагах Эйлера:

```text
t=0.00: X_0.25 = 3/4 X_0    + 1/4 q(X_0,    0.00)
t=0.25: X_0.50 = 2/3 X_0.25 + 1/3 q(X_0.25, 0.25)
t=0.50: X_0.75 = 1/2 X_0.50 + 1/2 q(X_0.50, 0.50)
t=0.75: X_1    =                  q(X_0.75, 0.75)
tokens = argmax_vocab(X_1)
```

Между шагами сохраняется непрерывное X, включая отрицательные координаты;
новый шум, categorical sampling, argmax и clipping к нему не применяются.
Формула реализует `X_next=X+Δt*(q-X)/(1-t)`. Нормировка только входа embedding
не меняет ODE-state. В конце q лежит на симплексе; argmax применяется один раз.

```python
sample = model.sample_block(
    input_ids=prefix_ids, block_size=32, steps=4, seed=17, return_trace=True
)
# sample['tokens']: [1,31]
# sample['trace']: время, argmax до/после шага, endpoint argmax, норма скорости.
# Эти argmax только для наблюдения; обратно в модель они не подаются.
```

`sample_block` измеряет сырой flow без верификации; разнообразие задаёт Gaussian
seed. Отдельно `generate` использует AR-проверку: greedy либо прежнее coupled
sampling при temperature>0. В coupled-режиме предложения строятся из конечного
q с Gumbel-шумом; это другая процедура предложения, чем raw argmax-flow.
Проверяется совпадение **конечного проверенного** текста с AR на том же seed.
Полное совпадение сырого совместного распределения с AR не утверждается.

### Выполнение и контроль

`ops/fm_campaign.py` загружает только code archive + tokens + manifest в приватный
`wolfram74/flowdraft-fm-assets`. Токен доступа находится в игнорируемом локальном
файле с правами 0600 и в артефакты не включён. Сессии `flowdraft-fm60k-a4-sNNN`
запрашивают T4 и работают по 3 часа; окончательный checkpoint и банк переносятся
в приватный `wolfram74/flowdraft-fm-state` того же аккаунта.

Перед обновлениями весов GPU-preflight выполняет четырёхпроходный backward на
четырёх якорях, проверяет конечность градиентов, снимает sampling trace и сверяет
greedy/coupled генерацию с frozen AR. Сам preflight не обновляет веса. Далее
первые пять optimizer steps и каждый десятый печатаются как `FM_PROGRESS` с loss,
LR, памятью, временем и числом конечных обновлений. Статус RUNNING сам по себе
не считается подтверждением того, что обучение дошло до optimizer step.

Оркестратор проверяет ответ push, результат сессии и продвижение шага; при
ошибке обучения останавливает автоматические повторы. При исчерпании квоты
сохраняет тот же checkpoint/горизонт и ждёт возможности продолжить. Он зависит
от работающего локального процесса; это не облачный scheduler.

Локальные проверки: 33 CPU-теста, включая значения и градиенты sparse posterior
KL с дубликатами, последовательный AR rollout, изоляцию четырёх префиксов,
заморозку учителя, повторное чтение банков, resume optimizer/LR и наблюдательную
трассу сэмплера. Это не заменяет CUDA-проверку и не доказывает качество обучения.

Фактический GPU-preflight 06.11.2026: сессия
[`wolfram74/flowdraft-fm60k-a4-s003`](https://www.kaggle.com/code/wolfram74/flowdraft-fm60k-a4-s003),
версия 1, Tesla T4. `FM_PREFLIGHT_SUCCESS`: finite loss 7.961681,
четыре якоря × четыре прохода, конечные градиенты, совпадение greedy/coupled
проверенной генерации с AR. Пик allocated memory preflight — 4.5495 GiB;
память optimizer после первого обновления сюда ещё не входит. Первые две
сессии остановились до обучения из-за обвязки: автоматическая распаковка
архива Kaggle и путь Hydra при импортированном entry point. Обе причины
исправлены; они не являются пройденными шагами или дополнительными моделями.
Текущие `FM_PROGRESS` сохраняются в `kaggle_out/fm-bank60k/live.log`, последний
проверенный замер — `observed.json`; `state.json.step` обновляется по завершении
сессии и потому во время её работы может показывать предыдущий checkpoint.

Подтверждение реального обучения, 06.11 около 16:00 МСК: `FM_PROGRESS step=10`,
`finite_updates=4`, `overflows=6`, LR=1e-6, peak allocated=5.90347 GiB.
Шесть первых AMP-попыток были пропущены; счётчик Lightning включает их, поэтому
10 не следует называть десятью обновлениями весов. FM последнего microbatch
1.12543, ms 9.70405; это стартовые значения, не оценка сходимости.

Первые шаги с подготовкой новых банков занимают 100–105 s/optimizer attempt;
подготовка последнего microbatch — примерно 6 s. Первый полный проход —
80 000/16=5000 попыток: при таком темпе порядка **140 часов T4**. Это грубая
экстраполяция начального участка, общие префиксы могут уменьшить затраты.
После кэширования банков этот расход исчезает; скорость тёплого прохода
отдельно пока не измерена. Стоимость полного прогона нельзя считать равной
60k×начальному времени шага, но и подготовку банков нельзя считать бесплатной.

В s003 GradScaler стартовал со штатного масштаба и адаптировался сам. Локальная
обвязка для новых стартов подготовлена с initial loss scale=128; при resume
сохраняется scaler из checkpoint. Контроль в следующих сессиях учитывает
последовательные overflow, а не их сумму за всё обучение. Исправленный entry
вкладывается в приватный kernel source, его SHA256 печатается как
`FM_ENTRY_SHA256`. Уже работающая s003 этими правками не перезапускалась.

## Математические источники

- [Flow Matching](https://arxiv.org/abs/2210.02747): обучение условной скорости
  на интерполянтах; здесь использован дополнительный положительный вес времени.
- [Variational Flow Matching, §3](https://arxiv.org/html/2406.04843v2#S3):
  параметризация скорости через условное среднее endpoint. В этой реализации
  выбран squared loss, а не предлагаемый в CatFlow categorical CE.
- [Categorical Flow Maps](https://arxiv.org/abs/2602.12233): обучение конечных
  переходов — отдельная задача. Его self-distillation losses здесь не включены.
- [Importance Sampling: Intrinsic Dimension and Computational Cost](https://arxiv.org/abs/1511.06196):
  ограничения importance sampling и нормированных оценок в большой размерности.
