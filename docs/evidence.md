## E1. Выпущенный Orthrus обучает Q, K, V **и O**, а не только Q, K, V

*3 октября 2026.*

**Утверждение.** В весах `chiennv/Orthrus-Qwen3-1.7B` двойник выходной проекции
`o_proj_diff` обучен так же сильно, как q/k/v. Раздел 3 статьи
(arXiv 2605.12825) называет обучаемыми только `W_Q, W_K, W_V`.

**Доказательство.** Двойники инициализируются копией AR-весов
(`copy_diff_from_ar` в их коде), поэтому необученный двойник совпадает с
оригиналом. Средний относительный сдвиг `‖W_diff − W‖ / ‖W‖` по 28 слоям:

| Двойник | Сдвиг |
|---|---|
| q_proj_diff | 0.318 |
| k_proj_diff | 0.352 |
| v_proj_diff | 0.315 |
| **o_proj_diff** | **0.341** |
| q_norm_diff | 0.001 |
| k_norm_diff | 0.002 |

**Это полное обучение, а не LoRA**, хотя в их `config.json` есть поля `r: 16`
и `lora_alpha: 32`. У LoRA ранга 16 разность весов лежала бы в 16 направлениях.
Здесь 90% её энергии набирается только на ~900 из 2048 направлений, а на
16 главных приходится 8–14%.

**Независимая проверка по их же тексту.** Статья пишет «около 16% параметров».
Для Qwen3-8B (скрытый размер 4096, 36 слоёв, 8 KV-голов по 128):
- только Q, K, V — 0.91B обучаемых из 9.1B, **10%**;
- Q, K, V и O — 1.51B из 9.7B, **16%**.

Для 1.7B у нас при перекладке вышло 357.6M из 2.08B, 17%.

**Воспроизвести.** `PYTHONPATH=. python tools/import_orthrus.py chiennv/Orthrus-Qwen3-1.7B out.ckpt`.
Вывод: [results/orthrus-release-1.7b-import.txt](../results/orthrus-release-1.7b-import.txt).

**Следствие.** Наша ветка `qwen06_orthrus` (Q, K, V) соответствует тексту
статьи, но слабее выпуска на целую проекцию. Её правильное название —
«Orthrus по описанию статьи», не «как опубликован». Для пары с выпуском
добавлен `qwen06_orthrus_qkvo` (сравнение C10).

## E7. Учёт последнего цикла у нас и у авторов различается

*3 октября 2026.*

Наш цикл всегда драфтит полный блок из 31 позиции. Принятое сверх
`max_new_tokens` обрезается после проверки, но в `acceptance` засчитывается.
Их цикл в последних 32 токенах лимита укорачивает блок до остатка
(`diff_len = min(block_size, max_length − start_idx)`).

Это различие в определении, а не ошибка. Но из него следует:
- наше `acceptance` на коротких генерациях чуть завышено относительно их
  определения (обе наши ветки одинаково, контрасты не страдают);
- со статьёй сравнивать по `tpf`, где последний цикл учтён честно.

Связано с известным смещением `tpf_steady` на один проход за генерацию
(+1.6% при 64 токенах).

## E10. Лишние проходы драфтера не окупаются по скорости — у нас и у авторов

не выполняется ни на одном переходе ни у одной ветки: TPF FlowDraft падает
1.788 → 1.422 → 1.185 → 1.038 (n1 → n4v). В таблице 3 статьи двухпроходный

Выигрыш многошагового **обучения** при одном проходе при этом есть: n1,
+0.360 ± 0.035 принятого токена против Orthrus (C3).

## E12. Ряд Тейлора для внимания драфтера неприменим ни в каком низком порядке

*4 октября 2026. Сравнение C11.*

**Утверждение.** В диффузионном проходе выпущенного Orthrus-1.7B центрированные
оценки `δ_ij = S_ij − S̄_i` не малы ни в одном из 28 слоёв, и масса внимания
сидит именно на больших `δ`.

**Доказательство.** По слоям: разброс `δ` 2.0–3.0, средний максимум 5.5–8.4.
Ключей с `|δ| ≤ 1.5` около половины (38–60%), но на ключи с `|δ| > 1.5`
приходится **83–97% массы внимания**. Относительная ошибка выхода внимания:
первый порядок 0.8–3.0, второй 0.5–2.3. Приёмка при замене рядом во всех слоях —
0.075 и 0.000.

**Почему.** В слоях 3–27 от 25% до 62% массы забирает первый токен (сток);
остальное — несколько острых ключей. Низкий порядок ряда переносит массу с них
на сотни прочих ключей.

**Математика.** Первый порядок даёт `o_i ≈ v̄ + C q_i/(n√d)`, где
`C = Σ_j v_j (k_j − k̄)ᵀ`. Это аффинная функция запроса, `W` и `b` которой
считаются из контекста — линейное внимание с `φ(u) = [1, u]`. Второй порядок —
уже дробь из квадратичных форм по `q_i`, и его состояние `Σ_j v_j ⊗ k̃_j ⊗ k̃_j`
занимает `d³ ≈ 2.1 млн` чисел на голову. Для Qwen3-1.7B это больше KV-кэша при
контекстах короче ~16 тыс. токенов.

## E13. `Wx + b`, подобранное по выходу внимания, — лучшая замена без обучения

*4 октября 2026. Сравнение C11.*

**Утверждение.** Линейный слой, подобранный в замкнутом виде по выходу внимания
этого же слоя, заменяет внимание в 8 из 28 слоёв ценой −0.225 принятого
токена (−6%), без единого шага обучения.

**Доказательство.** Таблица C11. Подгонка — гребневая регрессия
`[W b] = (XᵀX + λI)⁻¹ XᵀY` по 320 калибровочным состояниям, λ выбрана на
отложенной пятой части. Оценка — на других промптах. Относительная ошибка
выхода 0.16–0.66; одна константа `b` даёт 0.20–0.88, то есть `W` объясняет
заметную часть. Гребень почти везде упёрся в верх сетки (λ = 0.1), так что
регуляризацию стоит расширить.

**Память.** Целевая функция `‖A(x) − (Wx + b)‖²` при замороженной модели —
линейная регрессия. Нужны только моменты `XᵀX` и `XᵀY` за проходы вперёд;
backward не нужен.

**Чего это не даёт.** В Qwen3-1.7B веса внимания — около 20% весов прохода
(352M из 1.72B), остальное — MLP и выходной слой. Замена внимания в k слоях
экономит в проходе драфтера `k · (8.4M весов + KV этого слоя)`, а проход
проверки не меняется. При 8 слоях это около 2.7% цикла на контексте 2 тыс.
токенов и около 8% на 32 тыс. При потере приёмки −6% выигрыш по скорости на
коротком контексте отрицательный.

## E14. Как выбирать слои: не по тому, насколько хорошо приближается внимание

*4 октября 2026. Сравнение C11.*

Спирмен между статистикой слоя и потерей приёмки при его замене, слои 1–27:

| Статистика | выкинуть | ряд 1-го | ряд 2-го | копия AR |
|---|---|---|---|---|
| ошибка ряда 1-го порядка | −0.35 | −0.42 | −0.70 | −0.32 |
| доля массы на `|δ| > 1.5` | +0.04 | +0.19 | +0.02 | +0.21 |
| сдвиг двойника от AR при обучении | +0.48 | +0.77 | +0.50 | +0.28 |
| глубина слоя | +0.54 | +0.81 | +0.52 | +0.33 |

**Вывод.** Хуже всего приближаются ранние и средние слои, где внимание сидит на
стоке, но именно они для приёмки почти не важны. Связь с ошибкой приближения
**обратная**. Предсказывают важность глубина и то, насколько двойник ушёл от AR
при обучении: поздние слои важнее. Потери от замены складываются (C11), поэтому
по одному слою выбирать недостаточно. Нужен выбор с учётом уже заменённых —
жадный с переоценкой или обучаемые заслонки под бюджет. Оговорка: одна модель,
40 состояний.

## E15. Без обучения линеаризация драфтера не даёт ускорения ни в каком варианте

*4 октября 2026. Сравнение C11.*

**Утверждение.** Ни одна замена слоёв диффузионного вида линейной подгонкой в
замкнутом виде не ускоряет выпущенный Orthrus-1.7B: замена внимания,
целого слоя или только MLP.

**Доказательство.** C11. По одному слою замена почти везде бесплатна, но
потери складываются: каждый следующий слой получает уже искажённый вход.
Лучший вариант — только MLP: при 8–12 слоях скорость 0.97–0.99 от Orthrus.
Целый слой экономит больше, но теряет приёмку быстрее: 0.88 при 8 слоях.

**Следствие.** Направление «гибридного» драфтера живо только при обучении: после
замены оставшиеся слои должны подстроиться к искажённому входу, как в
двухэтапных схемах линеаризации (сначала подгонка выходов, затем дообучение).
Порог, который надо пройти: при 12 заменённых MLP (`c` = 0.766) приёмка должна
вернуться к ≈ 3.6 из 3.775 — это дало бы +9% к Orthrus. Пилот отменён 4.10;
проверяется гибридной парой на 100k (C10); до неё «статья про гибридный
драфтер» — гипотеза.
