# Дизайн функции потерь под многошаговость — версия после четырёх критиков

Ветка `dev/ys`, 5 августа 2026. Цель — сделать композицию прыжков
**осмысленной**: `A_n` должна расти по `n`. Сейчас `A_1 = 2.34`, `A_2 = 0.00`.

Первая редакция этого файла стояла на утверждении, что он-полиси таргет
уничтожает вырожденный минимум. **Это неверно, и ниже стоит правильный
аргумент.** Полугрупповой член выкинут: он убит независимо теорией и прайор
артом. Механизм переноса описывался с перепутанным знаком.

---

## 1. Диагноз

**Ф1. Все учительские таргеты целятся в `p_AR(· | префикс корпуса)`.** Значение
этого таргета состояние драфтера не меняет, поэтому чтение состояния не может
снизить лосс **ни при какой ёмкости** — вход просто пуст по релевантному
содержанию. Второй прыжок отличается от первого ровно и только входом.

**Ф2. Покрытие пар `(s,t)` есть, а таргет на нём корпусный.** `rollout_anytime`
уже супервизирует `π_{s,1}` при случайных `s`. Пробел не в покрытии, а в том,
что во всех этих точках цель одна и та же и от входа не зависит.

**Ф3. Арифметика.** `TPF = (A_n + 1)/(n + 1)`; безубыток второго прыжка —
`A_2 > 1.5·A_1 + 0.5`, при `A_1 = 3.13` это `5.2` из 7. Требуемое отношение
`A_2/A_1 = 1.5 + 0.5/A_1 ≈ 1.66` **почти не зависит от `K`**. Условие
арифметической невозможности — `1.5(A_1+1) − 1 > K−1`, то есть при `K=8` это
`A_1 > 4.33`; мы на 3.13, значит `n=2` арифметически **жив**, а мёртв `n=3`
(нужно 7.26 > 7). Прошлая редакция говорила «при K=8 многошаговость мертва
арифметически» — неверно. Она мертва **эмпирически**: 190 блоков,
`E[Δ] = −0.053`, 95% CI `[−0.130, +0.024]`, оракульный отбор `φ = 0`.

---

## 2. Что реализовано: он-полиси свип верификатора

Один замороженный AR-форвард по **собственному черновику** драфтера даёт:

```
draft¹ = argmax π_{0,1}(x₀)                    # уже посчитан
p⁽¹⁾_j = p_AR(· | ctx, draft¹_{<j})            # ОДИН форвард
вердикт: точный жадный принятый префикс + токен коррекции
```

Реализовано как `weights='ar'` в адаптере: замороженные веса прогоняются через
ту же блочную геометрию с `causal_in_block=True`. Проверено на живых весах —
результат **побитово** совпадает с обычным каузальным форвардом
(`max|Δ| = 0.0`, argmax 100%), кэш не отравлен, бидирекционный контроль
расходится на 11.6 логита.

**Правильный аргумент, почему это работает.** НЕ «таргет зависит от состояния,
значит вырожденный минимум уничтожен» — при неограниченной ёмкости оптимум
этого члена по-прежнему константен по `x₀` и равен жадному продолжению AR,
которое вход не читает. Работает другое: **вход СОДЕРЖИТ частичное вычисление
таргета.** Таргет есть один AR-свип, применённый к черновику, а черновик есть
вход. Для сети, не выражающей точное отображение «контекст → цепочка» за один
форвард, чтение входа — самый дешёвый путь к ответу. Это утверждение об
ограниченной ёмкости, и защищать его надо как таковое.

**Что композиция покупает.** Пусть `T(ctx,d)_j = argmax p_AR(·|ctx, d_{<j})` —
один свип Якоби. Если карта реализует `T` точно, индукция по позициям даёт

```
A_n >= min(n, K−1)
```

строго выше `A_1`, пока `A_1 < K−1`, при детерминированном верификаторе и без
единого нового бита. Но сама гарантия даёт `TPF <= 1` — ровно скорость AR. Всё
выше единицы берётся из того, насколько оператор лучше своей гарантии.
**Член делает многошаговость осмысленной, а не дешёвой.**

Два побочных эффекта, оба ценные и оба бесплатные:
- вердикт становится **точным**: приёмка судится против `p_AR`, обусловленной
  собственным префиксом черновика, а не корпусным. Индикатор `c_j`
  (`teacher_chain_tail_weight`) этим заменяется на измеренную величину;
- **приёмка на каждом шаге обучения** как метрика — то, ради чего всё делается,
  до сих пор было видно только через декод по паре промптов.

Оговорка: таргет — argmax замороженного форварда, градиента не несёт и движется
вместе с драфтером. Это DAgger, со всей его неустойчивостью; вес надо рампить.

## 3. Перенос между циклами: знак был перепутан

Сдвиг окна на `A+1` кладёт перенесённые позиции в **начало** нового блока,
свежие — в хвост. Значит амортизация достаётся **мелким** позициям, а глубокие
всегда свежие. Прошлая редакция утверждала обратное.

Это по-прежнему стоит иметь: приёмка есть конъюнкция по префиксу,
`E[len] = Σ_j Π_{i≤j} a_i`, поэтому выигрыш на первой позиции умножает всю
цепочку. Но предсказание другое: растёт `acceptance_pos_01`, а отношение
`pos_j/pos_01` **падает**. И это не многошаговость — цикл остаётся один прыжок
плюс верификация; величина `A_2/A_1` его не тестирует вообще.

**Содержимое хвоста не несём.** Всё после разрыва драфтилось при условии
токена, который верификатор переписал: контрфактическая ветка, а не устаревшая
оценка. Идея «переносить логиты верификатора, они уже посчитаны» снята: там,
где они чисты (точка разрыва), правильный токен уже стал якорем; всё, что
переносится, обусловлено заменённым токеном.

**Найденный конфаунд, который делал замер нечитаемым.** Включение переноса
одновременно (а) подмешивало прошлый хвост и (б) переключало форвард на
попозиционный путь времени, где позиция 0 объявляется при `t=1` — кондиционирование,
стоившее 1.16 TPF само по себе. Измеренный обвал от переноса: `ΔTPF = 1.164`.
Совпадение до третьего знака. Две руки различались двумя вещами сразу.
Разведено: `decode.carry_content` (`draft|random|none`) и `decode.carry_time`.
Рука `random` — плацебо: те же времена, то же содержание по форме, содержимое
из независимого розыгрыша приора.

## 4. Что выкинуто

**Полугрупповой член** `KL(sg[π_{u,1}(X_{s,u}(x_s))] ‖ π_{s,1}(x_s))`. Убит
дважды.
- Теория: его неподвижная точка есть в точности «композиция = одиночный
  прыжок», то есть `A_n = A_1`. Член, купленный ради многошаговости, **запрещает**
  её. При `u→1` он вырождается в диагональ в пиковом входе — ровно тот
  тавтологичный `EC`, который уже опровергнут. Плюс тождество неточно для этой
  параметризации: код подставляет среднее в `π_u`, а башенное свойство требует
  усреднения `π_u`, и softmax не аффинен.
- Прайор арт: flow-map-дистилляция по полугруппе на симплексе словаря сделана,
  включая KL-форму и stop-grad на композиции.

**`rollout_kl`** — 0. Та же карта `π_{s,1}`, но при случайных `s`, тогда как
он-полиси член берёт то `s` и то состояние, которые расписание производит. Та же
гипотеза, правильное входное распределение, вдвое дешевле (около 23% шага).

## 5. Новизна: что осталось защитимого

- Он-полиси таргет и вердикт-как-супервизия — **стандартная практика**
  (DistillSpec и далее; в 2026 дважды, один раз в нашей же архитектурной семье).
  Продавать нельзя. Остаётся одна щель, названная самим конкурентом: маскирующий
  блочный драфтер **не имеет входного канала** для обусловливания на префикс и
  потому приближает такую супервизию **со стороны лосса**, обрезая носитель CE.
  Непрерывное состояние на симплексе — и есть этот канал.
- Перенос хвоста — три слоя прайор арта по отдельности (Ouroboros; перенос
  скрытых состояний верификации; rolling-диффузия с попозиционным шумом;
  warm start диффузионного драфтера). Не найдено **склейки**: непрерывновременного
  категориального драфтера внутри лосслесс-цикла, где хвост входит при `s>0` с
  попозиционным временем. Отдельно проверить `Set Diffusion` (2607.01775) — по
  названию и авторству самый вероятный полный прайор арт.
- Есть прямое встречное измерение: переиспользование черновика почти
  бесполезно при длине спекуляции 3–16, а мы на `K=8`.

## 6. Что мерить

Замеры прошлой редакции были поставлены на слабый инструмент и на неверные
пороги. Исправлено:

1. **Спаривать по промпту.** Корреляция между руками `ρ = 0.906`; спаривание
   снижает sd разности с 0.51 до 0.159, то есть **10× по числу промптов**.
2. **`A_2/A_1`** — порог не «больше 1.0», а `1.66` экономически. Для научного
   утверждения «композиция осмысленна» правильный порог всё же 1.0, но обе
   величины надо репортить раздельно, иначе рецензент прочтёт +20% как успех
   при −20% TPF. И мерить это надо спаренным блочным инструментом
   (`decode.diagnose_restart`, MDE 0.11 токена), а не попромптовым (MDE 0.33–1.12).
3. **`acceptance_pos_j` — это функция ВЫЖИВАНИЯ `S_j`, не хазард.** Отношение
   `S_j/S_1` падает экспоненциально даже при идеально плоском хазарде. Хазард со
   второй позиции уже плоский (0.711 ± 0.02) — выположивать нечего. Единственная
   позиция, где отношение равно хазарду, — `pos_02/pos_01`.
4. **Три руки одного чекпоинта, спаренные:** контроль (`onpolicy_s=0`), перенос,
   плацебо (`carry_content=random`). Плацебо отделяет содержимое хвоста от
   эффекта попозиционного кондиционирования — без него две руки различаются
   двумя вещами.
5. **`val/tpf` селектится при `jumps=1`.** При `jumps=2` метрика измерена
   ровно нулевой, и отбор чекпоинтов весь прогон шёл бы по шуму.

Отрицательный контроль: если `A_2/A_1` не сдвинулся, следующий подозреваемый —
ёмкость драфтера, а не целевая функция; при ограниченной ёмкости именно она
связывает, и члену больше нечего дать.
